CHAPTER 01 / THE BIG PICTURE

A language, its hosts,
and a learning path.

The opening chapter introduces JavaScript’s character before giving a fast tour of syntax. It establishes a useful distinction: the language itself is not the same thing as the environment in which a program runs.

01 / What it is

Dynamic and expressive

JavaScript is a high-level, interpreted language. It supports object-oriented and functional styles, and its variables can refer to values of different types over time.

02 / Where it runs

Language ≠ platform

The core language supplies values, operators, objects, and functions. Browsers add page, input, and network APIs; Node.js offers file, process, and server capabilities.

03 / A naming note

JavaScript and ECMAScript

ECMAScript is the standardized language specification; JavaScript is the familiar name used in practice. Despite the name, JavaScript is a distinct language from Java.

04 / How to learn

Experiment in short loops

Use a browser developer console or Node’s interactive prompt to test expressions. When examples grow, move them into a .js file and run them with Node or load them into a web page. Change a value, predict the result, then check it.

05 / The route ahead

From details to design

The book builds from syntax and values to expressions, statements, objects, functions, classes, modules, asynchronous programming, and host APIs.

CHAPTER 01 / THE TOUR

The pieces you’ll
see everywhere.

The syntax tour is intentionally quick: it gives names to familiar building blocks and shows how they fit together, saving the detailed rules for the chapters that follow.

A first mental model

Values, expressions,
and actions.

Expressions produce values; statements organize actions and change program state. Functions package reusable behavior, while objects group related data and methods.

  • Values numbers, strings, booleans, null, and undefined
  • Collections objects use named properties; arrays use ordered numeric positions
  • Operators calculate, compare, and combine values
  • Control flow if, loops, and function calls direct execution
  • Modern syntax arrow functions, classes, and optional chaining appear in the tour
an original example / app.js
// Small original example: data + function + control flow
const readings = [12, 18, 15, 21];

function average(values) {
  let total = 0;
  for (const value of values) {
    total += value;
  }
  return total / values.length;
}

const report = {
  label: "Afternoon readings",
  mean: average(readings)
};

if (report.mean > 16) {
  console.log(report.label, report.mean);
}

CHAPTER 02 / THE SOURCE RULES

Before meaning,
there are tokens.

Lexical structure is the smallest layer of JavaScript syntax: the rules for how source text is split into meaningful pieces. This chapter covers the details that make code readable to both people and the parser—characters, comments, names, literals, and statement boundaries.

01 / Text & whitespace

Formatting is flexible

JavaScript is case-sensitive: score and Score are different names. Spaces, tabs, and most line breaks separate tokens but otherwise don’t change a program’s meaning, so use them to make code clear.

02 / Comments

Notes for humans

// comments end at the line break. /* ... */ comments can span lines, but cannot be nested. Comments are ignored by the parser except that they still separate surrounding tokens.

03 / Literals

Values written directly

A literal is a value appearing directly in source: 42, "hello", true, or null. The literal’s spelling is part of the program, unlike a value held in a variable.

04 / Identifiers

Names have rules

Names identify variables, functions, classes, and more. They generally begin with a letter, _, or $; later characters can also include digits. Reserved words such as return have language-defined roles and cannot be used as ordinary bindings.

05 / Unicode

More than ASCII

JavaScript source supports Unicode in strings, comments, and identifiers, with Unicode escape forms available when needed. Visually identical text can have different underlying code-point sequences; normalize external text before comparing or using it as a key.

06 / Semicolons

Automatic insertion has limits

Semicolons can be omitted in many line-ending positions, but line breaks are not simply interchangeable with semicolons. A following ( or [ can continue the previous expression, and a newline immediately after return ends it early.

A reliable habit

Use semicolons consistently; keep sensitive syntax together.

Consistency makes boundaries easy to see. In particular, keep a return value on the same line as return, and be deliberate when a new statement begins with a parenthesis or bracket. These simple habits avoid common automatic-semicolon-insertion surprises.

CHAPTER 03 / DATA & STATE

Values have types.
Names hold references.

This chapter moves from source syntax to the things programs manipulate: values, types, and variables. It explains JavaScript’s primitive data, its objects, how conversion works, and how declarations control the lifetime and visibility of names.

01 / Numbers

One Number type, finite precision

Number represents integers and fractions using binary floating point. Some decimal fractions therefore round unexpectedly. NaN signals an invalid numeric result; Infinity represents overflow or division by zero. BigInt supports very large exact integers, but is a distinct type and does not mix implicitly with Number.

02 / Text

Strings and templates

Strings are immutable sequences of text. Quotes and escape sequences form string literals; template literals use backticks for multiline text and embedded expressions. Regular expressions provide a compact tool for matching and searching text.

03 / Other primitives

Boolean, null, undefined, Symbol

Booleans represent true/false. null commonly means an intentional absence; undefined often marks a missing value. Symbols create unique identifiers, often useful as object keys.

04 / Objects

Mutable values by reference

Arrays, ordinary objects, functions, and many built-ins are objects. Their properties can change. Assigning an object to another variable copies the reference, so both names can observe the same underlying object. Unreachable objects are reclaimed automatically.

05 / Conversion

Be explicit about intent

JavaScript converts values in some contexts—for example, when testing truthiness or combining unlike types. Prefer predictable explicit conversions and strict equality (===) when comparing values; loose equality (==) applies coercion rules.

06 / Variables

Bindings and scope

Use const for a binding you won’t reassign and let when reassignment is needed; both are block-scoped. const does not freeze an object. Legacy var is function-scoped and hoisted in ways that can surprise, so it is usually avoided in new code.

07 / Destructuring

Unpack structured data at the boundary.

Array and object destructuring bind selected values to local names. It can make function results and records convenient to work with; keep patterns simple enough that readers can see which value goes where.

CHAPTER 04 / EXPRESSIONS
Combine values.
Make meaning.
Expressions are the value-producing phrases of JavaScript. This chapter shows how property access, function calls, object creation, and operators combine into larger expressions—and why precedence, coercion, and short-circuit behavior matter.

      

        
01 / Expression forms
Values can be composed
Literals and names are basic expressions. Arrays and objects can be initialized inline; functions can be defined as expressions; properties can be read with dot or bracket notation, and functions can be invoked with arguments.

        
02 / Safe access
Optional chaining
?. stops a property or method-access chain when its left side is null or undefined, returning undefined rather than throwing. Use it where absence is expected—not to hide a broken assumption.

        
03 / Operators
Order changes the result
Operators have arity, operand/result types, and precedence. Parentheses make intent explicit. Precedence groups the expression; associativity determines grouping when operators of the same precedence repeat. Parenthesize complex combinations for readability.

        
04 / Arithmetic
Plus has two jobs
Arithmetic includes numeric operations and unary operators. + adds numbers, but can concatenate after string conversion when a string is involved. Bitwise operators work on integer representations; use them for bit-level tasks, not ordinary arithmetic.

        
05 / Comparisons
Test without surprises
Prefer === and !== to avoid implicit conversion in equality checks. Relational comparisons order numbers or strings; in checks for a property name, while instanceof checks a prototype relationship.

        
06 / Logical expressions
Short-circuit, return values
&& and || stop once the result is determined and return one of their operands—not necessarily a Boolean. ! negates truthiness. ?? falls back only for null or undefined.

        
07 / Assignment & tools
Expressions can change state
Assignments (including compound forms) produce a value as they update a binding. The conditional ?: chooses between two expressions; typeof, delete, await, and the comma operator have specialized uses. Avoid eval() for ordinary program logic.

        
A practical rule
Know what an operator returns—not just what it tests.
Logical operators are often used to select values because they short-circuit. The nullish coalescing operator is useful when only missing values should trigger a default, whereas || also treats 0, false, and the empty string as fallback cases.

CHAPTER 05 / STATEMENTS
Expressions are phrases.
Statements move the program.
Statements are JavaScript’s executable commands: they sequence work, branch on conditions, repeat actions, declare names, and handle control transfer. This chapter surveys the structures that turn expressions into complete program flow.

      

        
01 / Statement basics
Actions and blocks
An expression statement evaluates an expression for its effects. Curly-brace blocks group statements; an empty statement does nothing and is occasionally intentional, but can also hide a stray-semicolon bug.

        
02 / Branching
Choose a path
if/else selects work based on truthiness. switch compares a value against cases and normally continues through later cases unless you exit explicitly; use break when fall-through is not intended.

        
03 / Repetition
Loop over work
while tests before each pass; do/while tests after, so it runs at least once. A classic for combines setup, test, and update. for/of iterates values from an iterable; for/in iterates enumerable property names.

        
04 / Jump statements
Change the next step
break exits a loop or switch; continue skips to the next loop pass. Labels can target an outer loop, but should be used sparingly. return leaves a function, while throw signals an exceptional condition.

        
05 / Errors
Recover or clean up
try/catch handles exceptions; finally runs cleanup whether the try succeeds or fails. Keep cleanup reliable, and rethrow errors when the current layer cannot meaningfully handle them.

        
06 / Declarations
Names are statements too
let, const, and legacy var declare bindings. Function and class declarations define reusable abstractions; import and export connect modules. "use strict" opts older scripts into stricter rules.

        
07 / Modern control flow
Async and generators add suspension points.
await suspends an async function until a promise settles. yield pauses a generator and exposes a value to its caller. The legacy with statement is discouraged because it makes name lookup unpredictable; debugger is a development aid.

      

      

        
Interactive flow trace
Follow the loop, one statement at a time.

function summarize(records) {
  let total = 0;
  for (const record of records) {
    if (!record.active) continue;
    if (record.stop) break;
    total += record.value;
  }
  return total;
}

  console.log(summarize(records));
} catch (error) {
  console.error("Could not summarize records", error);
}

CHAPTER 06 / OBJECTS
Properties make
objects useful.
Objects group values under property names, but they are more than simple dictionaries: they are mutable, dynamic, and connected through prototypes. This chapter focuses on creating objects and working with their properties, from everyday access to the details behind inheritance and serialization.

      

        
01 / The object model
Named properties, shared references
An object maps string or Symbol keys to values. Properties may be data or accessors. Objects are mutable and assigned by reference, so different bindings can observe the same object.

        
02 / Creating objects
Literals are the everyday tool
Use object literals for records; constructors and built-in APIs create specialized objects. Object.create(proto) makes an object with an explicit prototype, including null when you need no inherited properties.

        
03 / Read and write
Dot or computed access
item.title is concise when the key is a known identifier. item[key] computes the property name at runtime and supports keys that aren’t identifier-shaped. Writes can add or update own properties.

        
04 / Prototype chain
Lookup can be inherited
If a property is not found directly on an object, JavaScript searches its prototype, then the prototype’s prototype, continuing up the chain. An own property can shadow an inherited one; deleting it may expose the inherited value again.

        
05 / Presence & enumeration
Own is not the same as visible
in checks own and inherited properties. hasOwnProperty checks only own properties. Object.keys() lists own enumerable string keys; for/in can also visit inherited enumerable keys.

        
06 / Copy & serialize
Copies are usually shallow
Object.assign() and object spread copy own enumerable properties into a target or new object. Nested objects remain shared references. JSON serialization is a data interchange format with limits: it omits or transforms some values and can’t represent cycles.

        
07 / Property behavior
Methods, accessors, attributes
Modern literals support shorthand, computed keys, spread, Symbols, concise methods, getters, and setters. Properties also have writable, enumerable, and configurable attributes, which govern assignment, enumeration, and deletion.

        
A practical rule
Choose a data structure for the job.
Objects work naturally for records with named properties and prototype-based behavior. When you need arbitrary keys with no prototype behavior, consider Map; when you need a sequence, use an array. Avoid confusing inherited properties with data owned by a record.

CHAPTER 07 / ARRAYS
Ordered data.
Useful operations.
Arrays are JavaScript’s indexed, ordered collections. This chapter moves from creating and accessing elements to iteration and the rich set of methods for transforming, searching, sorting, and reshaping sequences.

      

        
01 / Fundamentals
Zero-based and dynamic
Array elements are addressed by integer-like indexes starting at 0; length is one greater than the last index. Arrays can grow or shrink, and their elements may contain any mix of values.

        
02 / Creation
Prefer clear construction
Array literals are the common choice. Spread copies iterable elements into a new array. Array.of() treats arguments as elements; Array.from() builds an array from an iterable or array-like value. A single numeric argument to Array() means length, not one element.

        
03 / Length & holes
Missing is not undefined
Increasing length creates empty slots; reducing it truncates elements. Deleting an index leaves a hole without shifting later values. Sparse arrays can behave differently across iteration and methods, so dense arrays are easier to reason about.

        
04 / Iteration
Choose the right loop
for/of visits array values. Index-based for loops give direct control over positions. Avoid using for/in for array elements: it enumerates property names and can include non-index or inherited properties.

        
05 / Transform
Map, filter, reduce
Iterator methods such as map(), filter(), some(), every(), and reduce() express common collection tasks. They do not all return the same kind of result; choose by whether you need a transformed array, a test, or an accumulated value.

        
06 / Mutating methods
Know what changes in place
push()/pop() and shift()/unshift() add or remove at the ends. splice() edits a range in place; slice() returns a shallow portion without changing the source. Sorting also mutates the array.

        
07 / Search & shape
Find, flatten, combine
Search methods locate values or indexes; provide a comparator for numeric sorting because default sort compares string forms. flat()/flatMap() reshape nested data, while concat() combines sequences. Multidimensional arrays are arrays of arrays, not special matrices.

        
08 / Related structures
Array-like is not necessarily an array.
Some objects have numbered properties and a length but lack array methods; convert them when needed. Strings have indexed text access but are immutable, and their UTF-16 representation means an index is not always the same as a user-perceived character.

      

      

        
Interactive array workbench

CHAPTER 08 / FUNCTIONS
Reusable behavior.
First-class values.
Functions are one of JavaScript’s central abstractions: they package behavior, travel as values, and carry access to the scope in which they were created. This chapter explains how functions are defined, called, parameterized, and composed into higher-order patterns.

      

        
01 / Defining functions
Declaration, expression, arrow
Function declarations name reusable behavior. Function expressions create values, often for callbacks. Arrow functions are concise and capture this lexically; they are not constructors and should not replace methods that need their own receiver.

        
02 / Calling functions
Invocation sets the context
A plain call, a method call, and a constructor call have different behavior. For regular functions, this depends on how the function is invoked. call()/apply() choose a receiver immediately; bind() creates a function with a fixed receiver.

        
03 / Parameters
Defaults, rest, spread
Default parameter values apply when an argument is omitted or undefined. Rest parameters gather remaining arguments into an array; spread expands iterable values at a call site. Destructuring can unpack object or array arguments into named parameters.

        
04 / Functions as values
Pass behavior around
Functions can be assigned, stored in objects, passed as arguments, and returned from other functions. That makes callbacks and higher-order functions natural tools for customizing behavior and building abstractions.

        
05 / Closures
Remember the surrounding scope
A nested function retains access to lexical bindings from its outer function even after that outer call has returned. Closures enable private state, factories, and callbacks—but retained references can also keep data alive longer than expected.

        
06 / Function objects
Functions have properties too
Functions expose useful properties such as name and length; traditional constructor functions also use prototype. Function objects have methods including bind(), call(), and apply().

        
07 / Functional techniques
Build behavior by composing functions.
Functional programming emphasizes functions that can be combined, passed into collection methods, and reused. Higher-order functions accept or return functions; partial application preconfigures some arguments; memoization caches results. Prefer clear functions with predictable inputs and outputs.

CHAPTER 09 / CLASSES
Objects with a
shared blueprint.
Classes provide a familiar way to define objects that share behavior, but JavaScript classes are built on the language’s prototype system. This chapter connects class syntax to constructors and prototypes, then develops inheritance, static behavior, and alternatives such as delegation.

      

        
01 / Classes & prototypes
Syntax on top of delegation
A class describes how to create instances and where shared methods live. JavaScript’s underlying model is still prototype-based: instances delegate property lookup through a prototype chain rather than receiving copied methods.

        
02 / Constructors
Initialize with new
A constructor initializes each instance. Calling a class without new throws. The prototype relationship is what connects instances to class methods; instanceof tests that prototype-chain relationship, not every notion of “type.”

        
03 / Methods
Shared behavior on the prototype
Methods declared in a class body are installed on its prototype and shared by instances. Getters and setters provide property-like accessors. Class bodies run in strict mode, and class declarations have their own initialization rules.

        
04 / Static members
Behavior belonging to the class
Static methods and fields belong to the class itself rather than each instance, making them useful for utilities, factories, or shared configuration. Instance fields create per-instance state; private fields use names prefixed with #.

        
05 / Extending classes
Subclass with extends
A subclass inherits from a base class. Its constructor calls super() before using this; it can add behavior or override inherited methods. A child method can call the parent implementation with super.method().

        
06 / Class hierarchies
Model only useful relationships
Inheritance can express “is-a” relationships, but deep hierarchies couple code and can become brittle. Delegation or composition—building an object from smaller collaborating objects—often offers a more flexible design.

        
A practical rule
Use a class when instances share a clear contract.
Define state and behavior together when that makes the API easier to understand. Keep constructors focused on initialization, prefer small cohesive methods, and avoid creating a hierarchy just to reuse a few lines of code.

  constructor(width, height) {
    this.width = width;
    this.height = height;

CHAPTER 10 / MODULES
Organize code
around clear seams.
Modules let programs be assembled from separate files with explicit boundaries and dependencies. This chapter moves from closure-based patterns and Node’s CommonJS system to standardized ECMAScript modules used by modern browsers and Node.js.

      

        
01 / Why modules
Encapsulate and compose
Modules divide a large program into units with focused responsibilities. Encapsulation limits accidental name collisions and exposes a deliberate public API. Before native modules, objects, classes, and closures could provide similar boundaries.

        
02 / CommonJS in Node
require() and exports
Node’s traditional CommonJS modules expose values through module.exports (or properties on exports) and load dependencies with require(). The exported value is the module’s public interface; keep it intentional.

        
03 / ECMAScript modules
Explicit imports and exports
ES modules use export declarations and import statements. Named exports let a module expose several bindings; a default export provides one primary value. Imports can be renamed, and exports can be re-exported from a barrel or facade module.

        
04 / Module scope
Each file has its own scope
Top-level declarations in an ES module are module-scoped rather than automatically becoming global variables. ES modules are strict by default. Imports are static, read-only live bindings, and a module is evaluated once per loaded module identity.

        
05 / Browsers
Load a module graph
A browser can load a module entry point with <script type="module">. Its imports form a dependency graph fetched by the browser; cross-origin rules and correct server responses apply. Module scripts are deferred by default.

        
06 / Dynamic loading
Import when needed
import() loads a module dynamically and returns a Promise, useful for conditional features or splitting work. import.meta.url provides the current module’s URL, which can help locate related resources.

        
A practical rule
Make dependencies visible and APIs small.
Prefer explicit imports and exports for new code. Separate stable public names from implementation details, avoid tangled circular dependencies, and choose a module system that matches the runtime and build setup rather than mixing formats casually.

      

      

        
Interactive module map

CHAPTER 11 / STANDARD LIBRARY
Useful tools beyond
the core syntax.
This chapter tours built-in objects and APIs that JavaScript programs use every day. The library extends the core language with specialized collections, binary data, text matching, dates, serialization, locale-aware formatting, URLs, and host-provided utilities.

      

        
01 / Collections
Set, Map, and weak collections
Set stores unique values; Map maps keys of any type to values and preserves insertion order. WeakMap/WeakSet hold object keys weakly, making them useful for metadata tied to object lifetimes; they are intentionally not enumerable.

        
02 / Binary data
Typed arrays and buffers
Typed arrays expose fixed-width numeric views over binary buffers, useful for files, network formats, and performance-sensitive data. DataView gives more control over reading and writing different numeric types and byte orders.

        
03 / Pattern matching
Regular expressions
Regexps describe text patterns for matching, searching, splitting, and replacing. String methods such as match(), replace(), and split() integrate with them; flags change matching behavior. Test global expressions carefully because they maintain state.

        
04 / Dates & errors
Time is not just a string
Date represents an instant as milliseconds from an epoch, while display depends on time zone and locale. Use ISO timestamps for interchange and format for people explicitly. Built-in error classes communicate common failure categories.

        
05 / JSON
Interchange, not cloning
JSON.stringify() converts supported data into JSON text; JSON.parse() reads it back. JSON is a data format, not the full JavaScript object model: it cannot represent cycles, functions, Symbols, or undefined values.

        
06 / Internationalization
Let the locale do the formatting
The Intl API provides locale-sensitive number and date formatting and string comparison. Supply an explicit locale and options when output must be predictable; avoid hand-formatting decimal separators or date strings.

        
07 / URLs
Parse structured addresses
URL parses and manipulates URLs by component; URLSearchParams helps read and update query parameters safely. Prefer these APIs over manually splitting URL strings.

        
08 / Host utilities
Console and timers
Console methods aid inspection and diagnostics. Timers such as setTimeout() and setInterval() schedule work through the host environment. These APIs are widely available, but they are supplied by browsers or Node—not by the ECMAScript core itself.

        
A practical rule
Use the purpose-built API; know what it guarantees.
Choose Map for arbitrary keys, Set for uniqueness, Intl for human-facing formats, and URL/JSON APIs for their defined data formats. Standard library methods have specific edge cases—check whether an operation mutates, what values it omits, and which runtime provides it.

CHAPTER 12 / ITERATORS & GENERATORS
One value at a time.
Only when needed.
Iterators provide a shared protocol for stepping through sequences. Generators make that protocol easier to implement by letting a function pause at each yielded value and resume later, preserving its local state between steps.

      

        
01 / Iterable vs iterator
A source and its cursor
An iterable can produce an iterator. Its Symbol.iterator method returns an iterator object whose next() method returns a result with value and done. Iterables include arrays, strings, maps, and sets.

        
02 / Consumption
Many features use the protocol
for/of, spread, and destructuring consume iterables. This lets custom collections plug into familiar syntax without needing to be arrays. Each iterator typically tracks its own progress.

        
03 / Build an iterator
Define next()
A hand-written iterator controls how values are produced and when it is finished. It can represent a range, stream, or stateful traversal without storing every result in memory first.

        
04 / Early exit
Close iterators cleanly
Some iterators provide return() to release resources or finish early. Constructs such as for/of call it when iteration exits prematurely, giving custom iterators a chance to clean up.

        
05 / Generators
Pause with yield
A generator function, written with function*, returns a generator object that is both iterable and an iterator. Each yield pauses execution; the next request resumes from that point with local state intact.

        
06 / Delegation
Compose with yield*
yield* delegates iteration to another iterable or generator. It is useful for flattening nested sequences or composing generator-based routines while leaving the iteration protocol to the delegated source.

        
07 / Generator control
Generators can receive input and control signals.
The caller can pass a value to a suspended yield expression with next(value); it can also finish a generator with return() or inject an exception with throw(). These advanced controls make generators useful as cooperative state machines, though ordinary iteration is the common case.

CHAPTER 13 / ASYNC JAVASCRIPT
Wait for work.
Keep the program moving.
JavaScript’s host environments frequently perform work that finishes later—timers, user events, and network requests. This chapter explains the patterns used to coordinate that work without blocking the main flow: callbacks, Promises, async/await, and asynchronous iteration.

      

        
01 / The async model
Host work completes later
The core language evaluates synchronous code, while browsers and Node provide asynchronous APIs. Completion is reported later through events, callbacks, or Promises, allowing the program to handle other work while waiting.

        
02 / Callbacks & events
Register what happens next
A callback is a function supplied to run when an operation completes or an event occurs. This is foundational, but deeply nested callbacks can obscure sequencing and make error handling harder to follow.

        
03 / Promise states
Represent eventual results
A Promise is initially pending, then settles once as fulfilled with a value or rejected with a reason. then() registers reactions; catch() handles rejection and finally() runs cleanup regardless of outcome.

        
04 / Composition
Chain work and errors
Each then() returns a new Promise. Returning a value continues the chain; returning another Promise adopts its eventual state; throwing turns the next result into a rejection. A single downstream catch() can handle failures from earlier steps.

        
05 / Concurrency
Parallel when independent
Start independent operations before waiting for them. Promise.all() fulfills when all inputs fulfill and rejects if one rejects; Promise.allSettled() reports every outcome. Await sequentially only when later work depends on earlier results.

        
06 / Async functions
Use await for readable flow
An async function always returns a Promise. await unwraps a fulfilled value or throws a rejection, so ordinary try/catch can express error handling. It pauses that async function—not the whole JavaScript thread.

        
07 / Async iteration
Consume values that arrive over time
Async iterables expose an asynchronous iterator protocol. for await...of requests each next item and waits for it, useful for streams or paginated sources. Async generators can produce such values incrementally.

        
A practical rule
Think about ownership, failure, and ordering.
Know whether operations are independent or sequential, ensure every failure has a handling path, and avoid assuming a timer or network response arrives immediately. Async patterns organize waiting; they do not make CPU-heavy synchronous work nonblocking.

CHAPTER 14 / METAPROGRAMMING
Programs that
shape programs.
Metaprogramming means controlling how JavaScript objects behave at a deeper level: defining property rules, customizing language hooks with Symbols, intercepting operations with Proxy, and mirroring operations through Reflect. These tools are most valuable for library authors—and powerful enough to use sparingly.

      

        
01 / Property attributes
Properties have rules, not just values
Every property has attributes such as writable, enumerable, and configurable, or accessor attributes get/set. Object.getOwnPropertyDescriptor() inspects them; Object.defineProperty() defines them precisely.

        
02 / Extensibility
Lock objects down in stages
Object.preventExtensions() blocks new properties, Object.seal() also blocks reconfiguration, and Object.freeze() additionally makes data properties read-only. Freezing is shallow: nested objects need their own protection.

        
03 / The prototype attribute
Inheritance is itself configurable
An object’s internal prototype can be read with Object.getPrototypeOf() and, cautiously, changed with Object.setPrototypeOf(). Prefer Object.create() when constructing an object with a chosen prototype from the start.

        
04 / Well-known Symbols
Hooks into language behavior
Symbols such as Symbol.iterator, Symbol.toPrimitive, Symbol.hasInstance, and Symbol.toStringTag let objects customize iteration, conversion, instanceof, and default string descriptions. They are protocol hooks, not ordinary string keys.

        
05 / Template tags
Give template literals custom meaning
A tag function receives the literal’s string parts and interpolated values, so it can build SQL fragments, HTML-safe strings, localized text, or other domain-specific results rather than a plain string.

        
06 / Reflect
Operations as functions
Reflect exposes object operations—such as get, set, has, and defineProperty—as functions that report success with return values. It pairs naturally with Proxy handlers, where forwarding to the target is common.

        
07 / Proxy
Intercept fundamental operations
A Proxy wraps a target with a handler of traps for operations such as property reads, writes, and enumeration. It can validate, log, provide defaults, or create virtual objects—but traps must respect proxy invariants tied to the target’s non-configurable properties.

        
A practical rule
Use the least magical mechanism that solves the problem.
Ordinary methods and accessors are easier to read than proxies and redefined descriptors. Reach for metaprogramming when building reusable infrastructure, enforcing invariants, or adapting an object to a protocol—and document the surprising behavior clearly.

CHAPTER 15 / JAVASCRIPT IN WEB BROWSERS
The browser is
the runtime.
This long chapter moves from the core language to the web platform: how scripts load, how events flow, and how JavaScript reads and changes documents, styles, graphics, network data, storage, and history. The DOM is the bridge between JavaScript values and the page a person sees.

      

        
01 / Scripts in pages
Loading shapes behavior
Scripts can be inline or external, classic or module, blocking or deferred. Module scripts are deferred by default and have their own scope; classic scripts share the global window namespace, so name collisions and execution order matter.

        
02 / Events
The page is event-driven
Register handlers with addEventListener(). Events travel through capture, target, and bubble phases; handlers can stop propagation or prevent the browser’s default action. Custom events let components communicate in the same style.

        
03 / Scripting documents
Select, inspect, change
querySelector() and querySelectorAll() find elements with CSS selectors. From there you can traverse relatives, read and set attributes, change text or HTML content, and create, insert, move, or delete nodes.

        
04 / Scripting CSS
Prefer classes over inline styles
Toggling classes with classList keeps presentation in stylesheets; inline styles suit one-off dynamic values. getComputedStyle() reports the final applied style, and geometry APIs measure positions and sizes in document or viewport coordinates.

        
05 / Web Components
Reusable custom elements
Custom elements, <template>, and Shadow DOM let you build encapsulated components with their own markup and styles. They formalize patterns that component frameworks also use, directly in the platform.

        
06 / Graphics & media
SVG, canvas, and audio
SVG is scriptable as DOM; <canvas> offers immediate-mode 2D drawing with paths, transforms, clipping, and pixel access. Audio ranges from simple playback to the WebAudio graph for synthesized and processed sound.

        
07 / Navigation & networking
Move and fetch without reloads
The History API (pushState()) updates the URL and back-button behavior for app-like navigation. fetch() returns Promises for HTTP requests; Server-Sent Events and WebSockets provide server push and two-way messaging.

        
08 / Storage & workers
Persist data; move work off-thread
localStorage/sessionStorage store small string key/value pairs, cookies serve HTTP state, and IndexedDB stores larger structured data. Web Workers run scripts in parallel threads that communicate by message passing, keeping heavy computation off the UI thread.

        
The security model
Pages are powerful because they are constrained.
The same-origin policy and related rules limit what a script can read from other origins, which is what makes running untrusted code on every page visit acceptable. Keep it in mind whenever you load cross-origin data, embed frames, or handle untrusted HTML—sanitize content you insert into the document.

CHAPTER 16 / SERVER-SIDE JAVASCRIPT WITH NODE
Same language.
A different host.
Node runs JavaScript outside the browser, with bindings to the operating system. The core language is familiar, but the platform APIs are new: processes, files, buffers, streams, networking, child processes, and worker threads—organized around an asynchronous, non-blocking style.

      

        
01 / Node basics
Programs, not pages
A Node program starts from a script file, reads command-line arguments from process.argv and environment variables from process.env, writes to the console or streams, and exits when no work remains. npm manages the packages such programs depend on.

        
02 / Async by default
Don’t block the event loop
Node APIs favor callbacks, Promises, and events over blocking calls, so one process can juggle many connections. Synchronous variants exist (often ending in Sync) and are handy in scripts, but they stall everything while they run—avoid them in servers.

        
03 / Buffers
Raw bytes on the server side
Buffer is Node’s class for binary data—closely related to Uint8Array—used when reading files and sockets. Convert explicitly between buffers and strings with an encoding such as UTF-8 so bytes are never interpreted by accident.

        
04 / Events
EventEmitter everywhere
Many Node objects extend EventEmitter: register listeners with on(), trigger them with emit(), and treat an unhandled 'error' event as an exception. This pattern underlies servers, streams, and processes.

        
05 / Streams
Process data in chunks
Readable, writable, duplex, and transform streams move data piece by piece instead of all at once. pipe() connects them; respecting backpressure—pausing when the destination is full—keeps memory bounded on large transfers.

        
06 / Files & processes
Working with the operating system
The fs and path modules read, write, and inspect files and directories, in callback, Promise, and synchronous forms. Child processes run external commands, and the process and os modules expose platform details.

        
07 / Networking
Clients and servers
Node’s http module builds servers and clients from request/response streams—the basis most frameworks extend. Lower-level net sockets support non-HTTP protocols when you need raw TCP.

        
08 / Worker threads
Real parallelism, by message
Worker threads run JavaScript in parallel and communicate with postMessage(), MessagePorts, and transferred or shared typed arrays. Unlike browser workers, Node workers can share memory with SharedArrayBuffer—and share its synchronization hazards.

        
The mental shift
One thread, many simultaneous operations.
Node’s efficiency comes from never waiting idly: start asynchronous operations, register what happens on completion, and keep handlers short. Long CPU-bound work blocks every connection, which is what child processes and worker threads are for.

CHAPTER 17 / TOOLS & EXTENSIONS
The ecosystem
around the language.
The final chapter looks beyond the language itself to the tools and extensions that surround professional JavaScript development. They help catch mistakes, standardize style, test behavior, manage dependencies, prepare code for browsers, and add optional type safety.

      

        
01 / ESLint
Lint for bugs and consistency
ESLint analyzes code without running it and reports suspicious or undesirable patterns—unused variables, accidental globals, risky equality, outdated declarations, and configurable style or correctness rules. Treat lint output as preventative maintenance; fix or consciously configure each warning.

        
02 / Prettier
Formatting without arguments
Prettier reformats code into a consistent style automatically. Its value is not one perfect layout but eliminating manual formatting decisions and noisy style diffs so reviews can focus on behavior.

        
03 / Jest
Automated tests close to the code
Jest provides a test runner, assertions, mocks, and coverage-oriented tooling. Tests describe expected behavior in executable form, making regressions visible when code changes. Test important behavior and edge cases, not implementation trivia.

        
04 / npm
Packages and reproducible installs
npm installs libraries, records direct dependencies in package.json, and uses a lockfile to reproduce an installation. Distinguish runtime dependencies from development tools and audit what a package brings into your project.

        
05 / Bundlers
Many modules, deployable assets
Webpack, Rollup, Parcel, and similar bundlers follow module dependencies and produce optimized files for delivery. They may also handle assets, code splitting, minification, and development servers. Bundling is a build concern, distinct from the module syntax itself.

        
06 / Babel
Transpile newer syntax
Babel converts modern JavaScript—and some extensions—into code supported by target environments. Syntax transforms differ from polyfills: transforming syntax does not automatically add missing runtime APIs such as a new built-in method.

        
07 / JSX
Markup-shaped expressions
JSX, popularized by React, lets markup-like syntax appear in JavaScript expressions; a compiler transforms it into function calls that construct UI descriptions. It is an extension, not standard JavaScript, so it requires a build step.

        
08 / Flow & type checking
Annotations catch mismatches early
Flow—and the related, widely used TypeScript approach—adds type annotations so a checker can catch wrong argument types, missing properties, unsafe unions, and similar mistakes before runtime. Types also document APIs, but they do not replace runtime validation of untrusted input.

        
Adopting tools wisely
Add tooling when it removes friction or risk.
A useful baseline is a formatter, a linter, tests for critical behavior, and a pinned dependency lockfile. Add bundling, transpilation, or types when project needs justify the extra build complexity. Tools serve maintainability; they should not become an end in themselves.

BONUS / AFTER THE 7TH EDITION
JavaScript kept
evolving.
This is not a chapter from the book. It is a short continuation covering important ECMAScript additions standardized after the 7th edition was published, so the guide does not stop in 2020. Support varies by browser and Node version, so treat each feature as something to check before relying on it.

      

        
ES2021 / Everyday conveniences
Clearer assignments and replacements
String.prototype.replaceAll() replaces every match without a global regular expression. Logical assignment operators ||=, &&=, and ??= assign only when the current value calls for it. Promise.any() succeeds with the first fulfilled promise and reports an AggregateError if all reject.

        
ES2022 / Classes & modules mature
Fields, privacy, and top-level await
Classes gained public and private fields, private methods, static fields, and static initialization blocks. Modules can use top-level await. Arrays, strings, and typed arrays gained .at() for negative indexing; Object.hasOwn() provides a safer own-property test; errors can record a cause.

        
ES2023 / Non-mutating arrays
Transformed copies, originals intact
findLast() and findLastIndex() search from the end. More importantly, toSorted(), toReversed(), toSpliced(), and with() return changed copies instead of mutating the original array—a better fit for immutable state and predictable UI updates.

        
ES2024 / Grouping & deferred promises
Useful data-shaping helpers
Object.groupBy() and Map.groupBy() collect items under keys returned by a callback. Promise.withResolvers() exposes a promise together with its resolve and reject functions, simplifying cases that previously required an awkward external-variable pattern.

        
ES2025 / Iterators & sets
Lazy pipelines and set algebra
Iterator helpers such as map(), filter(), take(), and toArray() process values lazily. Sets gained union(), intersection(), difference(), and related operations. The edition also added Promise.try(), RegExp.escape(), and import attributes for module metadata.

        
Adoption rule
New syntax is not the same as support
Babel or TypeScript can often transform newer syntax, but new built-in methods may need a sufficiently new runtime or a polyfill. Check the target browsers and Node version, use feature detection where failure is acceptable, and test the exact features you ship.

        
The through-line since 2020
JavaScript is becoming safer around mutation, asynchrony, and data transformation.
Recent editions favor returning new values instead of mutating shared data, make asynchronous coordination more ergonomic, and bring common collection operations into the standard library. The fundamentals from Chapters 1–17 still explain the language underneath these additions.
