Chapter 6 · Functions for the journeyman

Invocation determines a function’s context

For ordinary functions, the value of this depends primarily on how the function is called—not simply where it was defined. Choose an invocation style to see the context it supplies.

Choose an invocation
function describe() { return this.name; }

Resulting context
this → { name: "Ninja" }

When called as an object method, that object is the function’s context; inside the method, this refers to the object.

Arrow functions do not create their own this; they use the surrounding lexical context. A bound function keeps the context chosen by bind().

The main invocation patterns

Standalone call

In strict mode, an ordinary standalone function’s this is undefined.

Method call

Calling object.method() supplies object as the context.

Explicit context

call() and apply() invoke immediately with a chosen context; bind() returns a function with that context fixed.

Constructor call

new creates an instance and makes it the constructor’s this. Prefer class for modern constructor-style code.

Chapter 7 · Functions for the master

Closures: functions remember their lexical environment

A closure is a function together with access to the variables in the scope where it was created. That lets a function retain private state after its outer function has finished.

Independent closure counters

Each call to makeCounter() creates a separate lexical environment with its own private count.

function makeCounter(start = 0) {
  let count = start;
  return () => ++count;
}
Click either counter. They have separate retained state.

Closure state is persistent, not automatically shared: separately invoked outer functions create separate environments.

A closure can encapsulate state

Because the counter’s count binding is local to makeCounter, outside code cannot modify it directly. It can only interact through the returned function. This pattern is useful for private state and function factories; use it when it makes the interface clearer, not just because it is possible.

Chapter 9 · Objects, prototypes, and classes

Objects delegate property lookup through prototypes

Every ordinary object has a prototype. If a property is not found directly on the object, JavaScript looks up its prototype chain. Classes provide syntax for constructing objects and expressing inheritance on top of this object model.

Explore property lookup

Choose a property to see which object in this sample chain provides it.

↓ prototype link
Object.prototype

Select a property to follow the chain.
class Ninja {
  constructor(name) { this.name = name; }
  hide() { return `${this.name} disappears`; }
}
const ninja = new Ninja("Kuma");

The instance stores its own name; the shared hide method lives on Ninja.prototype. Methods are shared through the prototype, rather than copied onto each instance.

Class syntax does not replace prototypes. JavaScript classes use the prototype-based object model under the hood. Inheritance can be convenient, but composition and simple objects may be a clearer fit for many designs.
Chapter 10 · Dealing with collections

Choose a collection that matches the job

Arrays, sets, and maps solve different problems. Explore how a Set keeps values unique and how a Map associates keys with values.

Set: unique values

Add values to a Set. Duplicate primitives are ignored; insertion order is preserved.

Map: key → value

A Map associates keys and values. Keys can be values of any type, including objects.

Map is empty.
const capitals = new Map();

Quick guide: use an array for an ordered sequence, a Set for unique values, and a Map for key–value associations. Choose based on the operation and access pattern you need.

Move expensive work off the UI thread

Web Workers run JavaScript in a separate worker context. The page and worker exchange messages instead of directly sharing ordinary variables; the worker cannot manipulate the page DOM.
